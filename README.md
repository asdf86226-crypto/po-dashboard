# po-dashboard
발주현황 대시보드

## 재고 — 쉐어포인트(MMS)에서 가져오기

**📥 구매요청 및 재고 가져오기** 를 누르면 재고를 쉐어포인트에서 먼저 받습니다.

- 사내 로컬PC(MMS)가 평일 07~19시 매시간 이카운트 재고를 쉐어포인트 `TDC › 문서 › MMS` 에 올립니다.
- 대시보드는 회사 마이크로소프트 계정으로 로그인해 `MMS/태성정밀`, `MMS/플로우텍` 의
  `재고현황_최신.xlsx`(재고) · `품목정보_최신.xlsx`(등록 품목)를 읽고 품목코드별로 두 회사 재고를 합칩니다.
- 처음 한 번은 로그인 창이 뜹니다. 쉐어포인트를 못 읽으면 재고는 갱신하지 않고(지난 값 유지) 버튼 옆에 '갱신 못 함'으로 표시합니다.
  (예전 회사PC 재고 스크립트 → 구매요청 Apps Script 재고 경로는 없앴습니다)
- 공통 코드: `mms-sharepoint.js` (구매요청 · 판매현황 대시보드에도 같은 파일). 엑셀 읽기: `vendor/xlsx.min.js` (SheetJS).
- 앱 등록에 Microsoft Graph **Sites.Read.All**(위임) 권한이 있어야 합니다.

- **열 때 자동 반영**: 이 브라우저에 쉐어포인트 로그인 기록이 있으면, 열 때(그리고 30분 넘게 지나 다시 볼 때) 재고현황 파일의
  eTag 를 보고 바뀌었을 때만 받아 발주 목록의 '현재 재고'를 고친다(로그인 창은 띄우지 않음). 구매요청 가져오기는 지금처럼 버튼으로만

## 구매요청 대시보드와 연결

- 위쪽 **📝 구매요청 대시보드** 버튼으로 바로 이동합니다.
- 구매요청에서 가져온 발주 건의 **진행 단계 · 입고예정일**을 저장할 때마다 구매요청 Apps Script(`action: poStatus`)로 보냅니다.
  팀원은 구매요청 목록에서 "🧾 선적완료 · 입고예정 11/2" 처럼 볼 수 있습니다. **공급사 · 금액 · 송금 정보는 보내지 않습니다.**

## 입고 문제 기록

입고검사 · 사용(조립) 중에 발견한 문제를 품목코드별로 적어 두고, 그 품목을 다시 발주할 때 알려준다.

- **입고 문제** 탭 → `+ 입고 문제 기록`: 품목코드 · 발견일 · 공급사 · 발견 단계 · 문제점 · 다음 발주 때 요청할 내용
  (품목코드를 넣으면 가장 최근 발주의 품명 · 공급사를 채운다)
- 새 해외/국내 발주 등록 창에서 품목코드를 넣으면 코드 아래에 그 품목의 문제 기록이 바로 보인다
- 새 발주를 저장하거나 **구매요청 가져오기**로 등록하면, 미반영 문제가 있는 품목을 팝업으로 알린다
  (가져오기 창에도 `⚠ 입고 문제 N건` 표시)
- 상태: **미반영**(다음 발주 때 알림) → **반영됨**(발주에 넣음 · 다음 입고 때 확인) → **개선 확인**
- 품목코드는 그대로 비교한다 (`717062.0` 과 `717062` 는 다른 품목)
- 저장 위치는 다른 발주 자료와 같다(이 브라우저 · JSON 백업에 `qualityIssues` 로 포함)
- **사진**: 기록 창에서 스크린샷을 `Ctrl+V` 로 붙여넣거나 사진 파일을 끌어다 놓는다. 긴 변 1600px · JPEG 로 줄여
  브라우저 IndexedDB(`po_dash_qi`)에 따로 저장하고(발주 자료의 localStorage 용량을 쓰지 않음), JSON 백업에는 `qualityImages` 로 함께 들어간다.
  목록 · 발주 창 · 팝업에 작은 사진으로 보이고 누르면 크게 보인다
